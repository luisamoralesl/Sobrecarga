01

Concepto y reglas del lenguaje

Primero el significado; después la sintaxis.

¿Qué significa sobrecargar?

Es declarar una función especial, con un nombre de la forma operator<símbolo>, que define el comportamiento de un operador existente cuando intervienen objetos de clases o enumeraciones definidas por el programador.

Al declarar operator+ para Desplazamiento2D, la expresión a + b puede crear otro desplazamiento sumando sus componentes. La notación familiar delega el trabajo a una función.

✳
Sobrecargar no es inventar
No crea símbolos nuevos ni cambia cómo funciona int + int. Da un significado a un operador ya existente para un tipo definido por el usuario.

Restricciones que debes recordar

1

No hay operadores nuevos. Solo se sobrecargan operadores existentes que el lenguaje permita.

2

Al menos un operando debe ser de una clase o enumeración definida por el programador; no puedes redefinir int + int.

3

No se modifica la precedencia, asociatividad ni cantidad de operandos del operador.

4

::, ., .*, ?: y sizeof no pueden sobrecargarse.

5

operator=, operator[], operator() y operator-> deben declararse como miembros de clase.

6

Un método operator+ marcado const no modifica directamente el objeto izquierdo (*this).

7

La sobrecarga de && o || no conserva el cortocircuito habitual: ambos operandos se evalúan antes de llamar al operador.

8

Que el lenguaje permita una sobrecarga no la vuelve buena: el diseño profesional prioriza significados comprensibles.

Precaución: antes de diseñar un ejercicio con un operador, confirma que puede sobrecargarse y revisa sus restricciones.
02

Decisiones de diseño

Usa esta prueba antes de escribir operator.

¿El significado se anticipa?

Completa la frase: «El operador ___ aplicado a estos objetos significa ___». Si otra persona puede anticipar el resultado, probablemente vas por buen camino.

Interpretación natural

  • Duracion + Duracion: sumar tiempos.
  • Fraccion + Fraccion: suma aritmética.
  • Fraccion == Fraccion: equivalencia.
  • cout << objeto: representación legible.

Conviene cuestionarla

  • Alumno + Alumno: ¿qué resultado expresa?
  • Cuenta + Cuenta: ¿sumar saldos o fusionar cuentas?
  • Producto * Producto: significado no definido.
  • Usar + para borrar o guardar datos.

CASO 01

Desplazamiento2D · suma natural

operator+ miembro que crea un resultado nuevo.

Un robot avanza (3, 2) y luego hace un desplazamiento (−1, 4). La suma por componentes produce (2, 6). En UML, operator+ aparece como una operación pública normal de la clase.

Salida: Desplazamiento total: (2, 6)
Programa 1 · operator+ miembro
#include <iostream>
using namespace std;

class Desplazamiento2D {
private:
    double dx, dy;
public:
    Desplazamiento2D(double x, double y) : dx(x), dy(y) {}

    Desplazamiento2D operator+(const Desplazamiento2D& otro) const {
        return Desplazamiento2D(dx + otro.dx, dy + otro.dy);
    }

    void mostrar() const {
        cout << "(" << dx << ", " << dy << ")";
    }
};

int main() {
    Desplazamiento2D a(3, 2), b(-1, 4);
    Desplazamiento2D total = a + b;
    cout << "Desplazamiento total: ";
    total.mostrar();
    cout << endl;
}
Preguntas de análisis
  1. ¿Qué parte corresponde al operando izquierdo en a + b?
  2. ¿Por qué operator+ devuelve un objeto nuevo?
  3. ¿Qué aporta el const al final del método?
  4. ¿Sería apropiado usar + para borrar uno de los desplazamientos? Justifica.
CASO 02

Fraccion · suma, igualdad y salida

operator+, operator== miembro; operator<< externo.

La clase mantiene el denominador distinto de cero, lo hace positivo y simplifica con std::gcd (C++17). Así, las fracciones equivalentes comparten la misma representación normalizada.

ExpresiónSignificadoResultado
a + bSuma matemática de fraccionesFracción nueva
a == bMismo valor tras normalizarbool
cout << aEscribir en un flujo de salidaostream&
Salida: Suma: 5/6 · Iguales: true · Error: Denominador igual a cero
Programa 2 · tres operadores
#include <iostream>
#include <numeric>
#include <stdexcept>
using namespace std;

class Fraccion {
private:
    int numerador, denominador;

    void normalizar() {
        if (denominador < 0) {
            numerador = -numerador;
            denominador = -denominador;
        }
        int divisor = gcd(numerador, denominador);
        numerador /= divisor;
        denominador /= divisor;
    }

public:
    Fraccion(int n, int d) : numerador(n), denominador(d) {
        if (d == 0) throw invalid_argument("Denominador igual a cero");
        normalizar();
    }

    Fraccion operator+(const Fraccion& otra) const {
        return Fraccion(numerador * otra.denominador +
                        otra.numerador * denominador,
                        denominador * otra.denominador);
    }

    bool operator==(const Fraccion& otra) const {
        return numerador == otra.numerador &&
               denominador == otra.denominador;
    }

    int getNumerador() const { return numerador; }
    int getDenominador() const { return denominador; }
};

ostream& operator<<(ostream& salida, const Fraccion& f) {
    return salida << f.getNumerador() << "/" << f.getDenominador();
}

int main() {
    Fraccion a(1, 2), b(1, 3), c(2, 4);
    cout << "Suma: " << (a + b) << endl;
    cout << "Iguales: " << boolalpha << (a == c) << endl;
    try {
        Fraccion invalida(5, 0);
    } catch (const invalid_argument& e) {
        cout << "Error: " << e.what() << endl;
    }
}
Analiza el diseño
  1. ¿Por qué 2/4 y 1/2 se consideran iguales?
  2. ¿Por qué operator<< devuelve ostream& y no void?
Ubica la validación
  1. ¿Qué excepción protege el invariante?
  2. ¿Qué operaciones son métodos y cuál es función externa?

CASO 03

Contador · prefijo y posfijo ++

El parámetro int sin nombre distingue la forma posfija; no es una cantidad que se suma.

Ambas formas incrementan, pero devuelven valores distintos: el prefijo devuelve el objeto ya incrementado; el posfijo conserva y devuelve una copia anterior.

ExpresiónQué ocurreValor de la expresión
++cIncrementa primero; luego devuelve el objetoValor nuevo
c++Guarda copia previa; después incrementaValor anterior
Salida: Posfijo: 5 · Prefijo: 7 · Valor final: 7
Programa 3 · prefijo y posfijo
#include <iostream>
using namespace std;

class Contador {
private:
    int valor;
public:
    Contador(int inicio = 0) : valor(inicio) {}

    Contador& operator++() {       // Prefijo: ++c
        ++valor;
        return *this;
    }

    Contador operator++(int) {      // Posfijo: c++
        Contador anterior = *this;
        ++valor;
        return anterior;
    }

    int obtenerValor() const { return valor; }
};

int main() {
    Contador C(5);
    cout << "Posfijo: " << (C++).obtenerValor() << endl;
    cout << "Prefijo: " << (++C).obtenerValor() << endl;
    cout << "Valor final: " << C.obtenerValor() << endl;
}
Convención habitual: prefijo devuelve una referencia (Contador&) y posfijo devuelve una copia (Contador), para seguir el comportamiento esperado del incremento incorporado.
CASO 04

Calificaciones · subíndice seguro

operator[] miembro con validación de límites.

Una colección de tres notas permite consultar por índice. Los índices fuera de rango lanzan out_of_range. El operador devuelve int por valor para permitir consulta sin abrir la modificación directa.

Salida: Segunda nota: 90 · Error: Indice de calificacion invalido
Programa 4 · operator[] validado
#include <array>
#include <cstddef>
#include <iostream>
#include <stdexcept>
using namespace std;

class Calificaciones {
private:
    array<int, 3> notas{80, 90, 100};
public:
    int operator[](size_t posicion) const {
        if (posicion >= notas.size()) {
            throw out_of_range("Indice de calificacion invalido");
        }
        return notas[posicion];
    }
};

int main() {
    Calificaciones grupo;
    cout << "Segunda nota: " << grupo[1] << endl;
    try {
        cout << grupo[5] << endl;
    } catch (const out_of_range& e) {
        cout << "Error: " << e.what() << endl;
    }
}
Decisión intencional: como devuelve por valor, grupo[0] = 95 no permite modificar la nota. El operador se conserva solo para consultar; la modificación puede exponerse mediante un método validado.
CASO 05

Duracion · suma no miembro

Dos parámetros explícitos; acceso mediante la API pública y sin necesidad de friend.

La suma de dos actividades es una operación simétrica. La función externa puede consultar los minutos con un método público y construir una nueva duración.

Salida: Total: 60 minutos
Programa 5 · operator+ externo
#include <iostream>
using namespace std;

class Duracion {
private:
    int minutos;
public:
    Duracion(int m) : minutos(m) {}
    int obtenerMinutos() const { return minutos; }
};

Duracion operator+(const Duracion& a, const Duracion& b) {
    return Duracion(a.obtenerMinutos() + b.obtenerMinutos());
}

int main() {
    Duracion actividad(45), descanso(15);
    cout << "Total: "
         << (actividad + descanso).obtenerMinutos()
         << " minutos" << endl;
}
04

Operadores sobrecargados en UML

No existe una relación UML especial por usar un operador.

Cómo leer la firma

En UML se representa como una operación de la clase: nombre, parámetros, tipo de retorno y visibilidad.

El primer + de + operator+(otro: const Duracion&): Duracion señala que la operación es pública. El signo incluido en operator+ identifica el operador de C++.

Error frecuente: confundir el símbolo de visibilidad de UML con el operador + del método.
Duracion
+ Duracion(m: int)
+ obtenerMinutos(): int
+ operator+(otro: const Duracion&): Duracion

Guía rápida para elegir

Necesidad del dominioOperador posiblePregunta de validación
Combinar dos magnitudes compatibles+¿Se espera un resultado nuevo?
Comparar equivalencia de valores==¿La igualdad está definida?
Mostrar un objeto en consola<<¿La representación es clara y estable?
Avanzar una unidad de estado++¿Qué significa exactamente aumentar uno?
Consultar una posición[]¿Hay un índice natural y control de límites?

07

Conclusiones

Qué llevarte al siguiente ejercicio.

↗
La sobrecarga expresa operaciones familiares para tipos definidos por el programador, sin alterar las reglas esenciales de los operadores incorporados.
↗
El diseño empieza preguntando qué significa la operación para esos objetos, no escribiendo operator.
↗
const, el tipo de retorno y las validaciones son tan importantes como el operador elegido.
↗
En UML, los operadores se dibujan como operaciones de clase y no necesitan una relación especial.
↗
Si la sobrecarga aclara el código, es útil. Si crea ambigüedad conceptual, conviene un método con nombre explícito.

La pregunta que guía cada sobrecarga:

¿Una persona puede anticipar qué hará esta expresión?
